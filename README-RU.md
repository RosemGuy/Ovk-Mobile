# Ovk-Mobile alpha — 1.0

Клиент OpenVK для iOS 6 с локальной музыкой, оформлением в духе старого VK и музыкального плеера iOS 6. Objective-C/ARC, Xcode 5.1.1, OS X 10.9. Deployment Target 6.0, armv7/armv7s. Сборка 32-битная, подходит и для проверки на iPhone 5s с iOS 10.

## Музыка

В меню есть раздел «Музыка». Его обычная вкладка — «На устройстве». Она работает без подключения к OpenVK: на экране входа тоже есть кнопка «Музыка».

Передача файлов:

1. Через iTunes → устройство → Программы → Общие файлы → Ovk-Mobile. Файлы можно положить в Documents либо Documents/Music.
2. Через «Открыть в Ovk-Mobile» из другого приложения. Файл копируется в Music; оригинал сохраняется, повторное имя получает суффикс.
3. В симуляторе можно положить файлы в Documents/Music контейнера приложения и обновить список.

Поддерживаемые локальные файлы: MP3, M4A/AAC, ADTS AAC, WAV, CAF и AIFF; MP4 доступен как аудиофайл, если его аудиодорожку понимает iOS. Файлы из системной медиатеки iPod/Apple Music и DRM-записи не импортируются: локальная вкладка показывает файлы самого приложения. FLAC, Ogg/Opus и WebM штатным декодером iOS 6 не поддерживаются.

Импорт выполняется в фоне через временный файл, затем атомарно переносится на место. Незавершённые импорты не попадают в список. Пользовательские оригиналы не удаляются при остановке или смене трека.

## Плеер и фон

Чёрная панель, крупные кнопки, системные ползунки, метаданные и обложка из ответа API при наличии. Если обложка не предоставлена, показывается нейтральная заглушка. Музыка продолжает играть при выходе из экрана плеера, переходе в другой раздел, сворачивании приложения и блокировке устройства. Кнопка «Плеер» в разделе «Музыка» возвращает текущий экран.

Есть пауза, перемотка, предыдущий/следующий трек и автоматический переход к следующему треку текущего загруженного списка. На экране блокировки передаются название, исполнитель, длительность и позиция; поддерживаются удалённые команды play/pause/next/previous. После ручной паузы возврат в приложение не должен запускать трек сам. Выход из аккаунта останавливает плеер. При запуске видео текущая музыка ставится на паузу.

В Info.plist включён только фоновый режим audio. Категория аудиосессии — Playback. На подготовку/загрузку следующей записи в фоне выделяется конечное время: бесконечные фоновые скачивания не предусмотрены. Аудиодвижок AVAudioPlayer работает на постоянном NSThread с живым run loop; интерфейс получает снимки состояния в главном потоке. Поведение фонового аудио и экрана блокировки нужно проверять на реальном iPhone.

## Экспериментальное

Настройки → Экспериментальное (значок колбы):

- «Видеозаписи» добавляет видео в меню и открывает видео-вложения.
- «Музыка OpenVK» добавляет вкладку OpenVK внутри «Музыки» и открывает аудиовложения сервера. Используется выбранный при входе инстанс. Нужен аккаунт либо деморежим.

Оба переключателя выключены по умолчанию и сохраняются между запусками. При выключении серверная музыка/видео останавливаются, соответствующие элементы скрываются. Локальная музыка от этих переключателей не зависит.

Видео пока экспериментальное; музыка сервера теперь доступна обычной вкладкой. Ограничение воспроизведения остаётся: успешное воспроизведение всех роликов и устранение прежнего сбоя звука не подтверждены. Видео использует MPMoviePlayerController. Получаются доступные варианты MP4; если сервер явно выдаёт отдельный адрес звука, выполняется попытка соединения дорожек без универсального перекодирования.

## Лента, профиль и записи

Лента использует светлую шапку автора и даты, белое тело записи, нижнюю строку счётчиков и раскладку до трёх фотографий с переходом в полную галерею. «Ответить · N» открывает комментарии. Нажатие на текст — полную запись. Счётчик лайков информационный.

В профиле: тёмная шапка, аватар, настоящие данные пользователя, две кнопки, шесть счётчиков, полоса фотографий и фильтр «Все записи / Записи автора». Вкладка «Информация» показывает статус, город и описание. Неизвестные счётчики показываются тире. Кнопка действий предлагает открыть профиль в Safari или скопировать ссылку. Добавление/блокировка друзей не имитируется.

Новые текстовые записи публикуются кнопкой пера в новостях либо «Новая запись» в своём профиле. Редактор использует wall.post. В чужом профиле кнопка открывает сообщение. Комментарии загружаются через wall.getComments с подгрузкой; «Ответить» публикует комментарий к записи, нажатие на существующий комментарий позволяет ответить конкретно ему (reply_to_comment) и открыть его вложения/профиль автора. Публикация использует wall.createComment и доступна только если сервер разрешил can_post.

На время отправки кнопки и редактирование блокируются, чтобы не отправить дважды и не потерять новый текст. При ошибке редактор сохраняет текст. Автоматической повторной отправки нет: после обрыва сети перед ручным повтором нужно проверить, появилась ли запись. В деморежиме отправка отключена; добавлен пример чтения комментариев.

Адрес записи разбирается отдельно: владелец стены не смешивается с автором, поддерживаются отрицательные ID сообществ и проверяется номер записи/ответа. После успешной публикации обновляются соответствующая стена, запись и лента; если запрос уже идёт, обновление откладывается до его завершения.

Параметры сверены с исходником OpenVK: https://raw.githubusercontent.com/openvk/openvk/master/VKAPI/Handlers/Wall.php . Реальных публикаций из этой среды не выполнялось. Нативный тест параметров: bash tools/TestWallModel.command (здесь не запущен). Геометрия фотораскладки действительно скомпилирована и протестирована в Linux: bash tools/TestFeedLayout.command. Макет новых экранов — Feed-profile-preview.png, не скриншот симулятора.

## Фото

Сетка миниатюр, отдельная галерея, счётчик, кнопки и свайпы между кадрами, pinch и двойное нажатие. Во время увеличения свайп не меняет кадр. Для просмотра выбирается большой размер из API; миниатюры декодируются до 512 px, просмотр до 2048 px. Кэш изображений ограничен 16 МиБ.

## Сборка

Откройте OpenVKClassic.xcodeproj и схему OpenVKClassic в Xcode 5.1.1. Для симулятора — Cmd+R. Для устройства с джейлбрейком в Terminal виртуалки из папки проекта:

```sh
bash BuildIPA.command
```

Результат: dist/Ovk-Mobile-alpha.ipa. Скрипт собирает iphoneos, проверяет ARM-архитектуру, делает ad-hoc подпись и упаковывает Payload. Для такой установки нужен AppSync либо другой совместимый механизм подписи джейлбрейка. При ошибке открывается Build-result.txt, полный вывод находится в build-ipa.log. Нормальная установка без джейлбрейка требует собственного сертификата и provisioning profile.

## Вход, сеть и медиафайлы

Можно выбрать openvk.xyz, openvk.org или свой инстанс и API-домен. Вход использует /token, 2FA при необходимости, токен в Keychain или защищённом хранилище приложения при отказе прав Keychain. Сохранены User-Agent curl и дополнительный официальный корень ISRG Root X1 с проверкой хоста, срока и подписей. Нативный API-токен не добавляется к сторонним CDN-запросам. HTTPS→HTTP перенаправления блокируются.

Серверные аудио/видео сначала скачиваются полностью (до 256 МиБ; отдельный звук — до 64 МиБ), затем воспроизводятся. Это не потоковый плеер. Проверяются контейнер по байтам и полнота HTTP-ответа; реальные параметры аудиокодека читает AudioToolbox. Ошибочное расширение ссылки не считается доказательством формата. Поддержка конкретного кодека зависит от устройства и iOS. Универсальный декодер FFmpeg/VLC не включён.

В плеере «Сведения» показывает состояние и кодек для диагностики. Иконки из предоставленного RoteCode VK сохранены; происхождение и карта ресурсов — ICONS-SOURCE.md. Иллюстративный макет новых экранов — Music-preview.png (не снимок симулятора).

В Linux выполнены проверка OpenStep-проекта, включения исходников/ресурсов, plist/схемы, отпечатка X1, PNG и C-детектора контейнеров. Скрипт IPA проверен искусственными инструментами на успешную упаковку, ошибку компиляции и ошибку подписи. Это не нативная сборка.

```sh
python3 tools/validate_project.py
python3 tools/test_build_ipa.py
bash tools/TestMediaFormat.command
bash tools/TestFeedLayout.command
```

В OS X с Xcode доступны настоящие Objective-C-тесты; здесь они не запускались:

bash tools/TestMusicFiles.command
bash tools/TestPlaybackSession.command
bash tools/TestMediaModel.command

Первый тест проигрывает короткий тон и проверяет прогресс после первой секунды. Проверка импорта использует временную папку, а не настоящую медиатеку. Для сравнения звука самой macOS с симулятором: bash CheckSound.command. Ручные сценарии — SMOKE-TEST-RU.md.

Нативная сборка текущей alpha, воспроизведение на устройстве, фон, удалённые команды и Open In в этой среде не проверены: Apple SDK здесь отсутствует. Прежнее зависание пока наблюдалось пользователем только в симуляторе внутри виртуалки; обычный afplay в macOS работал.

## Alpha: Keychain при установке IPA

Сообщение «Сеанс не сохранён» относится к сохранению токена, а не к отказу OpenVK во входе. Теперь выводится числовой OSStatus. -34018 указывает на права подписи/entitlements, errSecInteractionNotAllowed — на недоступность защищённых данных/взаимодействия (в частности, заблокированное устройство).

BuildIPA.command для джейлбрейк-сборки теперь передаёт codesign собственный application-identifier и keychain-access-groups, ограниченные идентификатором приложения из собранного Info.plist. Это ad-hoc путь с AppSync, не замена действительному Apple provisioning profile. При обычной developer-подписи идентификаторы/префикс и права должны соответствовать профилю, который использует Xcode или установщик; переподпись сторонним инструментом может удалить права.

Пароль не сохраняется, токен не переносится в NSUserDefaults. При -34018, errSecNotAvailable или errSecAuthFailed на iOS используется файл Library/Application Support/Ovk-Mobile/sessions.json с NSFileProtectionComplete, правами 0600 и исключением из резервной копии. Это отдельный механизм защиты данных iOS, а не исправление подписи Keychain. При заблокированных защищённых данных сохранение не обходится. При возвращении доступа к Keychain сеансы мигрируют обратно при сохранении. Корректность подписи именно установленной на планшет сборки пока не подтверждена. Автоматические тесты упаковки проверяют наличие двух ограниченных entitlements, но не доступность securityd на iOS.

Источник Apple: https://developer.apple.com/forums/thread/114456 .

Проверено здесь: структура проекта, ресурсы, форматные подстановки 253 переводов, тесты C и сценарии BuildIPA с имитацией Apple-инструментов. Нативная сборка и отправка сообщений не проверены: в Linux нет Apple SDK.

## Светлая и тёмная темы

Настройки → Оформление → Тема: Светлая / Тёмная. По умолчанию светлая, выбор хранится на устройстве. Тёмная палитра применяется к навигации, ленте, диалогам, переписке, информации профиля, настройкам, комментариям и спискам медиа. Фото и видео не перекрашиваются; плеер и тёмная верхняя панель профиля сохраняют свой специальный стиль. Тема сайта исключена по пожеланию пользователя.

Проверить смену темы в обе стороны без перезапуска, сохранение после перезапуска, читаемость сообщений и настроек, сочетание с крупным текстом и English. Проверить переход из плеера обратно в клиент. Изменение темы не пересоздаёт аккаунт или плеер. Нативная сборка и визуальная проверка на iOS здесь не выполнены.

## Аккаунты, меню и iPad

Настройки → Аккаунты: добавить или переключить аккаунт, в том числе на другом инстансе. Идентификатор аккаунта — пара API-домен + user ID. Старый одиночный сеанс переносится при следующем успешном сохранении. Названия аккаунтов сохраняются вместе с токенами, в таблицу передаются только ID, имя и домен. «Добавить аккаунт» сохраняет предыдущие сеансы; обычный «Выйти» удаляет текущий. Закрытие приложения аккаунты не удаляет.

Настройки → Порядок меню: перетаскивание пунктов; порядок сохраняется. Музыка OpenVK доступна на вкладке OpenVK в разделе Музыка, экспериментальный переключатель оставлен только для видео.

На iPad боковое меню постоянно слева (240pt), контент справа, поддержаны обе ориентации и ограничена ширина ленты до 720pt. Нижняя панель поста: отдельный переход к комментариям и счётчик отметок; отметки пока информационные, отправка лайка не добавлялась. Рейтинг отображается на аватаре профиля, только если users.get возвращает числовое поле rating. Совместимость этого поля с конкретным инстансом не подтверждена. Нативные кнопки и сегменты получают цвета выбранной темы.

Добавлен tools/TestSessionStore.command для macOS: изолированный mock Keychain, миграция старого сеанса, несколько аккаунтов, одинаковые ID на разных доменах, переключение, выход и сохранение старых данных при отказе записи. Этот тест здесь не запущен из-за отсутствия Apple SDK. Файловый fallback и реальное сохранение на iPad требуют проверки на устройстве.

## Цветовые акценты и длительность MP3

Настройки → Оформление → Цвет: синий, фиолетовый, красный, зелёный, оранжевый, розовый. Цвет независим от светлой/тёмной темы; выбор сохраняется. Цветное тонирование сохраняет текстуры и альфа-маски исходных GUI-ассетов. Проверить переключение всех цветов, обычных кнопок и панелей в обеих темах, перезапуск и прозрачность скруглённых краёв. Музыкальный плеер сохраняет отдельный чёрный стиль.

Для MP3 длительность теперь рассчитывается по последовательности MPEG Layer III кадров файла, независимо от ошибочного Xing/Info значения. Для остальных/неподдерживаемых форматов остаётся AVAudioPlayer. Проверка выполняется в потоке аудио, не на UI. Это значение применяется к времени, шкале, seek и Now Playing. Общая длительность округляется до секунды. Удвоение не исправляется простым делением на 2.

Проверено: C-тесты VBR, неверного Xing, ID3, обрезанного файла; реальный синтетический MP3 213с, сравнение с ffprobe и намеренно удвоенный Xing. Результат счётчика округляется до 3:33. Файл пользовательского трека пока не предоставлен, поэтому его причина и результат в iOS не подтверждены. Проверить «Я сошла с ума» 3:33, перемотку к середине/концу и реальное завершение, остальные форматы WAV/M4A и экран блокировки.

## Архив записей

Пункт «Сайт инстанса» заменён на «Архив записей». При сохранённом порядке меню архив занимает место прежнего пункта сайта. Раздел запрашивает wall.get с owner_id текущего аккаунта, filter=archived, extended=1; поддержаны загрузка следующей страницы, открытие записей, комментариев и вложений. В деморежиме архив пуст, обычные записи не подставляются. Архивирование/возврат записей этим изменением не добавлялись.

API подтверждено исходником: https://github.com/openvk/openvk/blob/master/VKAPI/Handlers/Wall.php . В реальном аккаунте проверить архив с записями и пустой архив, переключение аккаунтов, сохранённый порядок меню, отсутствие пункта сайта, Русский/English. При ошибке сервера она должна отображаться в заголовке. Реальный запрос архива и нативная сборка здесь не проверены.

## iPad: Keychain -25308

Добавлена обработка errSecInteractionNotAllowed (-25308) резервным защищённым хранилищем, только когда UIApplication.isProtectedDataAvailable сообщает о доступности защищённых данных. При чтении недоступного существующего файла он не перезаписывается. Старые сеансы в недоступном Keychain восстановить таким способом нельзя; новый вход сохраняется в отдельном защищённом vault. Проверить на разблокированном iPad: вход → полное завершение приложения → запуск → восстановление, затем добавление второго аккаунта. При заблокированных защищённых данных fallback не выполняется. Проверить, что код -25308 больше не сопровождается ошибочным утверждением о непременно заблокированном устройстве. Нативная проверка на этом iPad не выполнена.

## Отметки и меню записи, сведения и пасхалка

Нажатие на сердце вызывает likes.add/likes.delete (type=post, owner_id, item_id). Счётчик и user_likes перечитываются с сервера, оптимистичных выдуманных чисел нет.
