# Проверка в Xcode 5.1.1

Эти сценарии ещё не выполнены на Apple SDK. Отмечать их пройденными следует только после проверки в виртуалке и на устройстве.

## Без аккаунта

1. Собрать схему OpenVKClassic для доступного iPhone Simulator. Проверить отсутствие ошибок компиляции и запуска.
2. Включить деморежим. Через кнопку меню открыть новости, друзей, сообщения и профиль, прокрутить новости, проверить фотографию, аватарки, длинный текст и кнопку «Назад».
3. В «Друзья» открыть Анну, затем «Сообщение». Открыть историю, редактор и отменить ввод. Отправка в деморежиме должна показать ошибку без изменения данных.
4. Потянуть список вниз. Убедиться, что индикатор заканчивает обновление. Нажать «Обновить» в конце списка.
5. В «Моя страница» открыть редактор записи. Проверить ввод, прокрутку над клавиатурой и отмену. Открыть «Настройки → Выйти из аккаунта» и вернуться на экран входа.
6. Повторить основные экраны на iPhone 3.5", iPhone 4" и iPad в портретной ориентации.

## С аккаунтом на тестовом инстансе

1. Проверить готовый выбор openvk.xyz. Переключиться на «Другой инстанс», ввести домен своего сервера, вернуться на openvk.xyz и снова на ручной ввод: введённый адрес должен сохраниться. Выполнить OAuth-вход, включая 2FA, если она включена. Проверить отмену входа. Повторить с токеном.
2. Проверить ленту, стену, друзей, фотографии и историю. Загрузить следующую страницу в списке с более чем 20 объектами; проверить продолжение списка.
3. Прочитать длинную запись, открыть её в Safari. Для explicit=1 текст и фотография должны быть скрыты в приложении.
4. Только на тестовом аккаунте отправить текст самому себе или согласованному получателю. Отправка происходит только после нажатия «Отправить». Проверить результат на сервере и обновление истории.
5. Только на тестовом аккаунте опубликовать пробную запись на своей стене и проверить её появление после обновления.
6. Перезапустить приложение, проверить восстановление сеанса из Keychain. Выйти, перезапустить: приложение должно показать вход.
7. Проверить неверный токен, недоступный сервер, отсутствие сети и отказ в доступе к переписке. Приложение должно показать ошибку, без бесконечного индикатора и без автоматической повторной отправки.
8. Отозвать сеанс на сервере. Ошибка авторизации 5 должна вернуть экран входа. Запросы старого сеанса после выхода не должны заполнять новый интерфейс.

При сообщении об ошибке приложите версию iOS, версию Xcode, домен инстанса и текст ошибки/лога компиляции. Токен и личную переписку из лога уберите.

## Меню версии 1.1

Проверить открытие и закрытие меню кнопкой и свайпом, переходы между разделами, сохранение их навигации и прокрутки, кнопку «Назад» на странице друга. Повторить переключение разделов несколько раз: один свайп должен открывать меню один раз. Проверить выход из деморежима через настройки.

## Исправление входа в версии 1.2

1. Нажать основную кнопку входа: должны появиться нативные поля логина, пароля и кода 2FA, без UIWebView.
2. Проверить пустой ввод, неверный пароль, правильные данные тестового аккаунта и вход с включённой 2FA. Пароль нельзя включать в сообщение об ошибке или лог.
3. Во время запроса нажать «Отмена». Форма должна закрыться и не открывать клиент после позднего ответа; повторный вход должен оставаться доступным.
4. Проверить отсутствие сети, TLS-ошибку, HTTP 403/HTML вместо JSON: должны появиться понятная ошибка и возможность повторить ввод.
5. Открыть «Альтернативный веб-вход»: проверить индикатор, сетевую ошибку, таймаут, отмену и успешное получение токена. Основной вход по паролю должен оставаться доступным после отмены.

Эти сценарии требуют Xcode/симулятора и тестового аккаунта; в Linux они не выполнялись.

## Раздельные домены — версия 1.3

Проверить пресеты xyz/org, ручной ввод сайта и API, авто-добавление HTTPS, проверку публичного API без учётных данных. Для org запрос должен идти на api.openvk.org, для xyz — на указанный пользователем адрес, без автоматического перенаправления пароля на org. Проверить восстановление обоих адресов из Keychain, открытие ссылок на сайте, выход и миграцию старого сохранённого сеанса без поля site.

## Версия 1.4

Проверить ovk.test без токена, JSON-ошибку при HTTP 400, обычную JSON-ошибку при HTTP 200, HTML при HTTP 403 и сведения host/path, MIME и Server в отчёте. Отчёт не должен содержать секретов или тела запроса/ответа. Проверить вход с явным v=5.131 и методы с access_token в POST-теле. Эти сценарии ещё не выполнены в Xcode.

## Версия 1.5 — ручная проверка

1. Открыть «Проверка защиты» на выбранном API-домене, проверить видимый адрес и страницу, затем вручную выполнить предлагаемую проверку. Пароль в этом окне не нужен.
2. Нажать «Готово». Успех разрешено показывать только после успешного нативного ovk.test с cookies браузера. На 403 окно остаётся открытым, показывается ошибка.
3. После успеха выполнить вход, открыть ленту и фотографии. Проверить общий UA и доменные cookies в разрешённом локальном тестовом окружении, не записывая секреты в логи.
4. Проверить отмену запроса и закрытие окна во время проверки. Поздний ответ не должен открыть другое окно.
5. На несовместимой странице проверить понятную ошибку; TLS и капча не должны обходиться автоматически. На API-ошибке 403 проверить действие «Открыть проверку».

Эти проверки на iOS ещё не выполнены.

## Версия 1.6 — адаптация OvkisserLiteiOS

1. Открыть список инстансов, добавить свой сайт и API, выбрать его, перезапустить приложение без токена и проверить восстановление выбора. Удалить свою запись свайпом.
2. Проверить вход без 2FA и с 2FA: диалог кода появляется только по ответу сервера. Отмена диалога не отправляет запрос, неверный код вызывает повторный запрос кода.
3. Проверить пароль со специальными символами без помещения его в URL/логи. HTTP 403 не должен показываться как ошибка пароля.
4. В OS X выполнить sh tools/TestAuth.command и проверить PASS. Тесты используют только вымышленные ответы, без обращения к реальному API.

Нативные проверки версии 1.6 в Linux не выполнялись.

## Версия 1.7 — User-Agent curl

Проверить API и вход на выбранном инстансе с User-Agent: curl. На ошибке HTTP/HTML диагностика должна показывать curl, в том числе после открытия «Проверки защиты» и после обновления с версии, сохранившей браузерный UA. Проверить загрузку аватарок и фотографий. TLS-ошибки должны по-прежнему завершать запрос ошибкой. Эти сетевые проверки ещё не выполнены.

## Версия 1.8 — доверие TLS

В OS X выполнить sh tools/TestTrust.command. В iOS 6.1 Simulator выбрать сайт openvk.org и API api.openvk.org, сначала проверить API без пароля. Если остаётся -1202, сохранить текст новой ошибки с именем хоста и датой. Проверить основной вход только после успешного пробного запроса. HTTP 403 после исправления TLS не является успешным входом. Проверить отсутствие принятия неверного имени или просроченного сертификата на локальном тестовом сервере.

Эти нативные тесты и живое соединение ещё не выполнены в среде подготовки.

## Версия 1.9 — медиа и оформление

1. Собрать и запустить на iOS 6.1 Simulator, затем на iPhone 5s/iOS 10. Проверить градиенты, рельефные кнопки, текcтуры, читаемость и меню после прокрутки.
2. В деморежиме открыть первую запись, все три вложения, отдельное фото с увеличением, WAV со звуком и MP4. Выйти назад во время загрузки и воспроизведения; плеер должен останавливаться.
3. Проверить три раздела медиа демоверсии, аватарки и фото профиля.
4. Войти в реальный аккаунт, проверить аватарки, фотографии из нескольких вложений, относительные CDN-URL, фото группы/пользователя и сообщения с вложениями.
5. Воспроизвести прямые MP3/AAC/MP4, проверить паузу, перемотку, время, окончание записи и полноэкранные controls видео. Проверить переход в Safari для внешнего видеоплеера.
6. Проверить отсутствие сети, 403/HTML вместо файла, отмену, отсутствие места и файл сверх лимита: должно быть сообщение об ошибке. Неверное имя сертификата не должно приниматься.
7. Открыть три медиараздела реального аккаунта, проверить пустой список, обновление и следующую страницу.
8. Проверить скрытую запись explicit=1 и скрытые репосты: их медиа не должны открываться из клиента.
9. В OS X выполнить sh tools/TestMediaModel.command. Это тест модели и URL без сетевых обращений; он не проверяет декодер или CDN.

Эти проверки на iOS версии 1.9 ещё не выполнены.

### Версия 1.11: оформление

- Профиль: шесть равных плиток, длинное имя не перекрывает статус; отсутствующие counters показывают тире.
- Чат: исходящие справа, входящие слева; длинный текст и фото не перекрывают время; после прокрутки видимость аватаров/пузырей/счётчиков не переносится на другую ячейку.
- Лента: дата под именем, счётчики под записью, фото не перекрывает текст.
- Вход: углы кнопки не растянуты, пароль и 2FA работают как прежде.

### 1.11.1 media — проверить на устройстве

- Полностью закрыть приложение, запустить демо, первым открыть аудиотон. Проверить звук, паузу, перемотку, конец/повтор.
- Открыть демовидео: должны быть и изображение, и тон. Затем проверить тот же реальный ролик, который имеет звук на сайте. При ошибке сохранить скриншот «Сведения».
- Переход между треками и возврат назад во время загрузки/подготовки: старое аудио не остаётся играть, повтор работает.
- Ошибка сети, неподдерживаемый файл, отдельная дорожка, несколько вариантов MP4. Не должно быть бесконечной подготовки или зависания интерфейса.
- Фото: последняя неполная строка сетки, переходы по кнопкам/свайпу, границы галереи. Увеличить фото и перемещать: кадр не должен переключаться; двойной тап возвращает масштаб.
- Быстро переключать кадры при медленной сети: старое фото не должно заменять новое.
- Вертикальное фото и альбом в посте: пропорции и выбор большого размера; открыть фото из ленты, пролистать остальные вложения.

Тесты на iOS в этой среде не выполнены.

### Alpha: воспроизведение без ухода в фон

1. Полностью закрыть приложение. Открыть демоаудио первым действием. Дождаться загрузки, не нажимая Home. Проверить, что интерфейс реагирует и звук запускается. Повторить после холодного запуска.
2. Демовидео H.264/AAC: звук и изображение без ухода из приложения. Затем тот же реальный ролик со звуком на сайте.
3. Во время подготовки уйти на Home и вернуться: не должно быть двух параллельных запусков; ручная пауза должна сохраниться после возврата.
4. Сменить трек сразу после первого запуска. Старое завершение подготовки не должно отключать новый звук.
5. Прерывание/выход назад/плохой файл: нет зависшего интерфейса, повтор доступен, звук не остаётся после закрытия экрана.
6. Если по-прежнему висит именно интерфейс: в Xcode нажать Pause и сохранить стек главного потока. Состояние паузы/нулевое время при работающем интерфейсе — отдельный сценарий.

### Alpha: новый движок AVAudioPlayer

- Полностью завершить приложение. Первый трек должен пройти дальше 1 секунды без Home; затем второй и третий треки.
- Во время подготовки уйти назад / выбрать другой трек / свернуть и вернуть приложение. Старый трек не запускается, ручная пауза сохраняется.
- Пауза, перемотка, повтор после конца, предыдущий/следующий, отключение сети при загрузке, некорректный файл.
- В «Сведения» аудио должно быть AVAudioPlayer, а не AVPlayer. Это подтверждает, что запущена новая сборка.
- Отдельно проверить видео: переписывание аудиодвижка не заменяет эту проверку.
