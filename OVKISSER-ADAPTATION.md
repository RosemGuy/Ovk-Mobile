## Что сделано в версии 1.6

В нашей реализации добавлены такие же параметры совместимости 2fa_supported=1 и client_name=openvk_legacy_ios. Запросы остаются POST с кодированием символов, пароль не попадает в URL. По need_validation открывается нативный диалог кода. Отмена диалога не выполняет новый запрос; повтор выполняется только после ввода кода пользователем. Неверный код снова запрашивает 2FA.

Добавлен список инстансов с выбором, добавлением и удалением своих адресов. Сайт и API можно задать раздельно. Последний выбор сохраняется без пароля и токена. Начальные пункты — openvk.xyz и openvk.org; старые домены из архива не объявляются рабочими автоматически.

Добавлен разбор сохранённого JSON HTTP 401 при NSURLErrorUserCancelledAuthentication (-1012), если старый NSURLConnection сообщает это вместо обычного завершения ответа. Ошибки сети и HTML 403 не превращаются в успешный вход или неверный пароль. Проверенный токен сохраняется в Keychain.

Исходник отправляет пароль через GET, синхронно ждёт сеть, хранит токен в NSUserDefaults и журналирует параметры методов. Эти приёмы не переносились. Реализация написана в существующих классах нашего приложения; исходные файлы, ресурсы и сторонние библиотеки из архива не копировались.

## Ограничения

Совпадение схемы входа не отменяет серверную защиту и не исправляет доверие сертификатам iOS 6. При HTTP 403/HTML или TLS-ошибке сервер ещё не вернул результат проверки логина. Успех соединения с реальным сервером этой версией не подтверждён.
