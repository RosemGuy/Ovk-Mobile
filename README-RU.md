# Ovk-Mobile alpha — версия 1.0

Нативный клиент OpenVK с оформлением по мотивам старого VK: градиентная синяя панель, объёмные кнопки, контурные иконки на рельефных подложках, фактура фона и тёмное выдвижное меню. Макет оформления находится в Style-preview.png; это иллюстрация по ресурсам, а не скриншот запущенной программы.

Xcode 5.1.1, OS X 10.9, Objective-C/ARC, Deployment Target 6.0, armv7/armv7s, iPhone и iPad. Без Swift и внешних библиотек.

## Сборка

Откройте OpenVKClassic.xcodeproj, выберите схему OpenVKClassic и симулятор, нажмите Cmd+R. Для устройства с джейлбрейком в Terminal OS X из папки проекта:

bash BuildIPA.command

IPA находится в dist/Ovk-Mobile-alpha.ipa. Для установки ad-hoc подписанной сборки нужен AppSync. Сборка 32-битная; пользователь планирует проверку на iPhone 5s с iOS 10. Для обычной установки на устройство задайте свой Bundle Identifier, сертификат и provisioning profile.

## Медиа версии 1.9

- Аватарки загружаются в ленте, списках, профиле и боковом меню через общий HTTPS-загрузчик с User-Agent: curl, cookies и дополнительным корнем ISRG Root X1. Имя сервера и срок сертификата проверяются.
- Нажатие на аватар в списке или профиле открывает просмотрщик фото.
- Нажатие на запись открывает её полный текст. Кнопка «Открыть фото, видео и аудио» показывает все поддерживаемые вложения. В переписке нажмите на сообщение с вложениями.
- Фото открывается отдельно; доступно увеличение жестом. Размер декодированного изображения ограничен 1600 пикселями по длинной стороне для уменьшения расхода памяти.
- Аудио и голосовые сообщения с прямой MP3-ссылкой воспроизводятся встроенным проигрывателем с паузой, перемоткой и временем.
- Видео с прямым MP4-файлом открывается во встроенном MPMoviePlayerController. Для экономии ресурсов предпочтительно качество 360p/240p; реальная поддержка кодека зависит от iOS и устройства.
- В боковом меню добавлены отдельные разделы «Фотографии», «Видеозаписи» и «Аудиозаписи» текущего пользователя с подгрузкой страниц.

Аудио и видео сначала скачиваются целиком во временный файл, затем воспроизводятся. Это не потоковый плеер. Предельный размер — 256 МиБ; для изображения — 20 МиБ. Загрузка отменяется при уходе из проигрывателя, его временный файл удаляется при закрытии контроллера. Изображения кэшируются в памяти с ограничением 16 МиБ.

Внешние веб-плееры без прямого файла предлагается открыть в Safari. DASH/HLS, WebM, OGG и Opus встроенный плеер этой версии не поддерживает. HEVC и другие современные кодеки могут не поддерживаться iOS 6/10, даже если файл имеет расширение MP4. Сервер может не выдавать прямой аудиофайл — клиент не обходит это ограничение.

Ссылка на медиа используется из ответа API. Нативный API-токен не добавляется к сторонним CDN-запросам; при загрузке используются только адрес файла и обычные доменные cookies. HTTPS→HTTP перенаправления блокируются. Ошибка/HTML вместо файла не передаётся проигрывателю как медиа.

Отправка фото, видео, звуков и смена аватарки не добавлялись: пользователь уточнил, что нужны просмотр и воспроизведение.

## Деморежим

В демоверсии есть вымышленные профили, фотографии, короткий аудиотон WAV и двухсекундное видео H.264 Baseline. Медиа доступны в первой записи ленты и в новых разделах, без аккаунта и сети. Отправка текста в деморежиме отключена.

## Вход и основные разделы

Сохранены новости, друзья, профили, сообщения, отправка текста и текстовых записей на стену. Меню открывается кнопкой слева или свайпом вправо на начальном экране раздела. Выход — «Настройки → Выйти из аккаунта».

Можно выбрать openvk.xyz, openvk.org или свой сайт и API-домен. «Список инстансов…» сохраняет свои адреса. Вход использует /token, 2fa_supported=1, client_name=openvk_legacy_ios; одноразовый код запрашивается при необходимости. Токен хранится в Keychain. Нативные запросы используют User-Agent: curl. В версии 1.8 пользователь подтвердил успешный вход в аккаунт.

Приложение включает официальный публичный корень ISRG Root X1 и пробует его после системной проверки доверия. Проверка имени хоста, срока и подписей остаётся активной; сертификат в системную связку ключей не устанавливается. Встроенные UIWebView по-прежнему используют системное доверие, а нативные API и загрузчик медиа используют OVKTrust.m.

Результаты исследования старого входа и происхождение решения — OVKISSER-ADAPTATION.md; прошлый аудит API — API-AUDIT-RU.md.

## Проверки и ограничения

В Linux проверены структура OpenStep-проекта, ссылки, исходники/resources build phases, схема, plist, отпечаток корня X1, подключение MediaPlayer/AVFoundation/ImageIO, PNG, WAV и параметры демонстрационного H.264-видео. Нативная сборка, реальная загрузка с CDN и воспроизведение на iOS версии 1.11.1 ещё не проверены: Apple SDK в среде нет.

Проверка структуры (Python 3): python3 tools/validate_project.py

Тесты настоящего Objective-C-кода в OS X с Xcode, без сети:

sh tools/TestAuth.command
sh tools/TestTrust.command
sh tools/TestMediaModel.command

Последний проверяет относительные/CDN-адреса, выбор размера фото, несколько вложений, MP4, аудио, MP3 голоса, репосты, скрытое содержимое и повреждённые поля. Эти нативные тесты в Linux не запускались; проверен синтаксис их shell-скриптов. Ручные сценарии — SMOKE-TEST-RU.md.

Нет push, Long Poll, комментариев, постановки лайков или управления друзьями. Ошибки сети не вызывают автоматическую повторную отправку сообщений. Поведение зависит от версии API инстанса и выдаваемых им медиафайлов.

Основные новые файлы: OpenVK/OVKMedia.m (загрузка и просмотр), OpenVK/OVKMediaModel.m (разбор объектов), OpenVK/OVKTrust.m (доверие TLS).

## Оформление 1.10 по референсам

Ориентир — пять скриншотов из Pictures/oldvk: графитовое меню, монохромные значки, синяя подсветка выбранного пункта, тёмная шапка профиля с сеткой счётчиков, синий фон формы входа. Это адаптация под существующие функции клиента, а не точная копия: отсутствующие функции оригинального VK не добавлены ради внешнего сходства. Счётчики берутся из users.get.counters; если сервер не вернул значение, отображается тире. Фото, видео и аудио открываются из плиток профиля.

Исходные скриншоты не включены в приложение. Ресурсы нарисованы программно: tools/reference_style.py (Pillow). Style-preview.png — иллюстративный макет, не снимок симулятора. На iOS нужно проверить меню, возвращение в выбранный раздел, профиль с длинным именем, собственную и чужую страницу, отсутствие counters, вход с клавиатурой и 2FA. Рабочие сетевые параметры входа, curl и проверка сертификатов не изменены.

## Медиа 1.11.1 на базе 1.11 с иконками RoteCode VK

Основное оформление и выбранные значки сохранены. Аудиоплеер на AVPlayer заменяет синхронное открытие AVAudioPlayer: проверка файла и готовности асинхронная, есть тайм-аут, пауза, перемотка, смена треков из текущего списка, системная громкость и обработка ошибок декодирования. Видеоплеер системный MPMoviePlayerController. AVAudioSessionCategoryPlayback включается для обоих типов записей. Исправлены обращения к NSURL, несовместимые с компилятором старого SDK.

Видео получает подробные данные через video.get, перебирает MP4-варианты и оригинал, если они явно предоставлены API. Если API выдаёт отдельный адрес звука, клиент пытается соединить дорожки через AVMutableComposition и passthrough export в MOV. Это не универсальный конвертер кодеков: неподдерживаемые форматы могут не воспроизводиться. Ошибка проверки дорожек на старой iOS не объявляется доказательством отсутствия звука в оригинале. При неудаче доступна кнопка «Сведения» с ключами API и числом обнаруженных дорожек, без добавления URL/токена приложением.

Фото: миниатюры по три в ряд, галерея с кнопками и свайпами, счётчик кадров, двойное нажатие и pinch. Во время увеличения свайп не переключает кадр. Смена фотографии отменяет старый запрос и защищена от запоздалых ответов. Миниатюры декодируются до 512 px, полноэкранный просмотр до 2048 px; кэш учитывает качество. Выбирается photo_max_orig либо самый большой sizes, затем старые photo_* поля. В ленте фото открывает галерею вложений и сохраняет пропорции, предоставленные API.

Медиа по-прежнему сначала скачивается целиком (256 МиБ для записи, 64 МиБ для отдельного звука, 20 МиБ для картинки). Это не потоковая передача. Демовидео теперь содержит H.264 Baseline + AAC LC, поэтому пригодно для проверки звука.

Проверены структура проекта, ресурсы, сценарии shell и наличие AAC в демовидео. Нативная сборка, холодный запуск и реальный звук не подтверждены в Linux: iOS SDK отсутствует. Нативные проверки модели доступны через tools/TestMediaModel.command в OS X. Они проверяют кандидаты видео, оригинал, отдельный звук, размеры фотографий, неверные поля и адреса.

## Исправление alpha: запуск аудио на iOS 6

Удалён вызов AVPlayer.volume / setVolume:, который отсутствует в iOS 6 и вызывал NSInvalidArgumentException. Громкость регулируется системным MPVolumeView и кнопками устройства. Версия приложения остаётся 1.0.

## Alpha: первое воспроизведение и возврат из фона

Операции AVAudioSession.setCategory/setActive, включая деактивацию, вынесены из главного потока в отдельный последовательный координатор OVKPlaybackSession. Активация происходит после готовности плеера, перед play. Каждому запросу соответствует уникальный владелец: запоздалое освобождение старого экрана не выключает сессию нового. До успешной активации подготовка не считается завершённой. Ошибка и тайм-аут остаются видимыми, интерфейс не ждёт окончания блокирующего системного вызова.

Добавлены обработчики ухода из приложения, возврата и аудиопрерываний. Возобновление сохраняет намерение пользователя: поставленный вручную на паузу трек не должен запускаться при возврате. Обработчики аудиоуведомлений передают изменения интерфейса на главный поток. Неподдерживаемый AVPlayer.setVolume не возвращён.

Предварительное отсутствие дорожек AVURLAsset больше не блокирует системный видеоплеер. Если API явно вернул отдельный звук, попытка соединения сохраняется; иначе файл передаётся MPMoviePlayerController для окончательного решения. Это не добавляет отсутствующую дорожку и не конвертирует неподдерживаемые кодеки.

Причина первого зависания не воспроизведена локально; описанные изменения устраняют обнаруженные проблемы управления сессией, но требуют проверки на iOS 6 и устройстве. Проверки координатора с искусственно заблокированным/ошибочным backend: `bash tools/TestPlaybackSession.command` на OS X. Они проверяют, что вызовы возвращают управление UI, устаревший владелец не деактивирует нового, ошибки передаются в главный поток. В Linux эти Objective-C-тесты не запускались. Версия приложения остаётся 1.0, архив — OpenVK-iOS6-alpha.zip.

## Alpha: диагностика звука в виртуалке и IPA

Пользователь уточнил: интерфейс работает, звук застревает на первой секунде, проверка пока только в симуляторе OS X 10.9 внутри виртуалки. Это не подтверждает такую же неисправность на iPhone. Архив не заявляется проверенным исправлением этого симптома.

Таймер прогресса, опрашивавший currentTime и duration, заменён периодическим time observer AVPlayer; длительность кэшируется после асинхронной загрузки asset. Observer удаляется до освобождения плеера. Во время воспроизведения доступна кнопка «Сведения»: состояние плеера, rate/время, аудиовыход и распознанные кодеки. Эти данные помогают отличить остановку движка от сбоя аудиовывода.

Запустить CheckSound.command в виртуалке: afplay воспроизводит двухсекундный WAV непосредственно через macOS, без клиента/симулятора. Зацикливание и здесь укажет на проблему ниже приложения; успешный тест не исключает отдельной ошибки симулятора.

BuildIPA.command: выбор Xcode для текущего процесса, проверка SDK и архитектуры, CODESIGN_ALLOCATE для самостоятельной подписи в Mavericks, явное отключение обоих вариантов CODE_SIGN_IDENTITY при сборке. После сборки проверяются приложение, ad-hoc подпись и ZIP. При ошибке сохраняется Build-result.txt и автоматически открывается в TextEdit. Без исходного build-ipa.log точная причина прежнего BUILD FAILED не установлена. Скрипт проверен искусственными инструментами в Linux на успешный путь, ошибку компиляции и ошибку подписи: python3 tools/test_build_ipa.py. Реальная сборка Xcode и установка на устройстве пока не выполнены.

Ролик пользователя: https://openvk.org/rosemdude?w=video15095_4 . Из этой среды не удалось получить страницу/API или скачать файл (DNS недоступен в shell, web тоже не открыл страницу). Кодеки и дорожки именно этого ролика здесь не проверены.

## Alpha: переписанный локальный аудиодвижок

Текущая аудиологика — OVKLocalAudio на AVAudioPlayer. Аудио не проходит через AVURLAsset/AVPlayer/AVPlayerItem, KVO или periodic time observers. Файл сначала скачивается; аудиосессия включается, затем декодер открывает файл и выполняет prepareToPlay. Все команды AVAudioPlayer (подготовка, play, pause, seek, stop и чтение позиции) выполняются на одной фоновой последовательной очереди. UI получает только снимки состояния в главном потоке. Возвращаемый BOOL от play проверяется, ошибки подготовки/декодирования показываются. Отмена не допускает запуска уже закрытого трека. Пауза/остановка завершаются до освобождения аудиосессии; позднее освобождение старого владельца не выключает новый.

Экран, выбранные иконки, версия 1.0, фотографии и видеоплеер сохранены. Эта правка специально меняет аудиодвижок; исправление видео со звуком ею не подтверждается. Нативная сборка и воспроизведение на iOS 6 в Linux недоступны. Проверка нового класса на OS X: `bash tools/TestLocalAudio.command` (тест проигрывает короткий тон). Проверяются отсутствующий файл, отмена, длительность WAV, прогресс дальше первой секунды, пауза, перемотка и остановка. Тесты добавлены, но здесь не выполнялись.
