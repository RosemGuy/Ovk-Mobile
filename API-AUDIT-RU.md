# Проверка совместимости API — 5 ноября 2026

Изучены доступные страницы документации и индексированная версия master OpenVK. Историю самых свежих коммитов GitHub загрузить не удалось; доступные исходники могли отставать от рабочего сервера. Изменение протокола, объясняющее HTML с HTTP 403 на openvk.xyz, не подтверждено.

## Что подтверждено по первичным источникам

- В Web/routes.yml сохранены /token и /oauth/token; методы вызываются через /method/.
- В VKAPIPresenter renderTokenLogin принимает username, password, grant_type и code через requestParam. Наш способ входа POST-формой соответствует этой схеме.
- Сервер принимает access_token / sid в параметрах, а также Authorization: Bearer. В версии 1.4 токен дополнительно передаётся в POST-теле для совместимости с прокси, которые не передают Authorization.
- processVKAPIVersion различает версию OpenVK 5.9999 и совместимые версии VK. Ошибки могут иметь разную оболочку и HTTP-статус. Версия 1.4 явно передаёт v=5.131 также при входе и читает JSON-ошибки до общей проверки HTTP-статуса.
- Ovk.test доступен без пользователя и возвращает информацию о версии и авторизации. Проверка подключения переведена на этот метод.

## Что означает текущая ошибка

Пользователь подтвердил, что HTTP 403 появляется на API-домене https://openvk.xyz. Ранее на скриншоте /token возвращал не JSON. Это не подтверждает смену методов API. Серверный запрет, фильтрация перед API или защита инстанса остаются возможными причинами. Точную причину без заголовков и доступа к серверу определить нельзя.

В сообщении разработчика OpenVK Legacy tretdm от 7 апреля 2026 отдельно описаны ограничения старых устройств, прокси и недоступность клиентского API под DDoS-защитой. Это объяснение общего класса проблем, а не доказательство причины конкретного отказа пользователя.

## Проверка без новой сборки

В версии 1.3 выбрать preset openvk.org, убедиться, что поле API содержит https://api.openvk.org, затем нажать проверку API без входа. Документация рекомендует этот домен для основного сервера. Эта проверка не отправляет пароль. Если он тоже возвращает 403, нужен диагностический ответ именно с этого адреса. Не следует автоматически переносить пароль с произвольного инстанса на другой домен.

## Изменения версии 1.4

Добавлены Accept: application/json и собственный User-Agent. При не-JSON ответе отображаются фактический API host/path, Content-Type и Server, без тела ответа, логина, пароля или токена. HTTP 4xx с корректной JSON-ошибкой разбирается как API-ошибка. Изменения совместимости не обходят серверную защиту и не гарантируют устранение HTTP 403.

## Ограничения проверки

Прямые сетевые запросы из Linux не работают из-за отсутствия DNS-доступа. Web-просмотрщик также не смог выполнить проверочные вызовы API. Apple SDK отсутствует. Проверены структура Xcode-проекта и упаковка; нативная сборка и живой вход версии 1.4 не проверены.
